# 로컬 볼트 조회와 편집

2026-09-16. 데스크톱의 데이터 경로는 Electron main → LocalVault → TaskRepository(`packages/tasknotes/repository.ts`) → TaskNotes Markdown이다. HTTP 서버나 Obsidian 플러그인 API를 실행하지 않는다.

## 선택과 파일 경계

- renderer에는 파일 시스템을 공개하지 않는다. 폴더 선택은 인자가 없는 IPC로 OS 선택창을 요청하고, 수정은 선택된 볼트·상대 경로·원문 해시·허용된 변경 필드만 전달한다.
- 최초 선택 시 TaskNotes 설정의 `tasksFolder`를, 없으면 TaskNotes 기본 폴더 `TaskNotes/Tasks`를 찾고, 둘 다 없으면 볼트 전체를 읽는다.
- 작업 폴더는 선택된 볼트 내부만 허용한다. 매번 읽기 전에 실제 경로와 디렉터리를 검증한다.
- 링크 디렉터리·파일은 따라가지 않는다. 숨김 경로와 node_modules는 탐색에서 제외한다.
- TaskNotes 설정의 작업 식별 방식(기본 `task` 태그, 또는 지정한 속성)에 맞지 않는 일반 노트는 건너뛴다. 잘못된 frontmatter, 읽기 실패와 링크는 누락 사실을 표시한다.
- 파일당 1MiB, 한 번에 읽는 본문 128MiB, 탐색 항목 25,000개, 깊이 16 제한을 둔다. 규모 제한에 도달하면 전체 성공이나 빈 목록으로 표시하지 않는다. 작업 폴더를 좁히면 된다.
- task 태그와 기존 한국어 속성을 지원한다. 영어 날짜·상태 필드 호환을 지원한다. 일반 Markdown 체크박스는 아직 지원하지 않는다.

## 저장과 갱신

`vault.json`에는 볼트 경로와 작업 상대 경로만 저장한다. 개발 실행은 `.local/desktop`, 패키지 실행은 Electron userData에 저장한다. 목록용 본문 캐시는 메모리에만 유지한다. 수정 전 원문과 복구용 경로 정보는 프로필의 `task-backups/<UUID>.md` 및 `.json`에 저장한다. 이 백업에는 개인 노트 원문이 포함되며, 자동 삭제하지 않는다. 기존 버전의 connection.bin/cache.bin은 읽거나 삭제하지 않고 보존한다.

파일 변경 이벤트를 감지하면 250ms의 연속 저장 대기 후 목록과 상세를 다시 읽는다. 연속 변경 중에도 최대 1초마다 갱신을 요청한다. 볼트의 디렉터리 이벤트를 구독하고 선택한 작업 폴더 범위만 반영하므로 작업 폴더 교체도 감지한다. 볼트 전환·선택 해제·앱 종료 때 이전 감시를 해제한다. 감시 오류 시 5초 후 재연결하며 목록 화면의 30초 주기 확인도 보조 수단으로 유지한다. 편집·드래그·상태 메뉴 중에는 화면 반영을 미뤄 초안과 선택한 원문 revision을 보존하고, 종료 후 다시 읽는다.

목록 화면을 다시 열거나 새로고침해도 파일을 다시 읽는다. 목록이 보이는 동안 30초마다 갱신하고, 상세·편집·상태 메뉴·설정·동작 메뉴·폴더 선택 중에는 주기 갱신을 멈춘다. 실행 중 일시적인 읽기 실패는 같은 볼트의 메모리 캐시만 오류와 함께 표시한다. 다른 볼트로 전환하면 캐시를 비운다. 앱을 재시작했는데 폴더가 없으면 오류와 볼트 변경 기능을 제공한다.

검색 페이지의 커서는 볼트·폴더·파일 변경 상태·검색어·분류에 묶인다. 다른 볼트나 바뀐 파일 상태에서 이전 페이지를 이어 읽지 않는다.

## 검증 범위

- 로컬 볼트 테스트: 자동 폴더 탐지, 일반 노트 제외, 숨김 경로 제외, 외부 파일 수정·삭제 반영, 원문 미변경, 링크·볼트 밖 경로 거부, 폴더 소실, 볼트/분류/파일 변경 시 검색 커서 거부.
- 실제 Electron 시험: 서버 입력 없음, 볼트 선택·취소, 검색·필터·키보드 조작, 숨기기·재표시, 재실행 시 선택 유지, 외부 수정, 폴더 오류와 복구, 볼트 전환 시 이전 목록 제거, 선택 해제의 재실행 유지.
- 시험은 합성 Markdown과 격리된 프로필에서 진행하며 native 폴더 선택 결과만 대체한다. 사용자 볼트 내용, 실제 Obsidian Sync 왕복, 물리적인 전역 단축키 입력과 Android는 별도 검증 대상이다. Headless 동기화 실행은 가짜 `ob`로 시험하며 실제 `ob`로는 읽기 전용 점검만 한다.

## 데일리노트와 목록을 맞춘 기준

업무/개인으로 나눈 데일리노트용 Base(TaskNotes의 Bases 보기)의 기준을 로컬 목록에 적용한다. 다른 Base 설정을 읽어 해석하지는 않는다.

- 선택한 작업 폴더(하위 폴더 포함)의 작업 중 상태가 완료가 아닌 노트를 고른다. 사용자가 다른 작업 폴더/볼트 전체를 선택하면 그 범위에서 찾는다.
- 예정일 또는 마감일이 오늘 이하이면 오늘 목록에 함께 표시한다. 과거 예정일만 있는 작업도 포함한다.
- 마감일이 오늘보다 이전이면 `(미룸)`을 붙인다(지난 예정일만으로는 붙이지 않는다). 미룸 여부 → 예정일 → 마감일 → 경로 순으로 정렬한다.
- 업무 태그가 있으면 업무로 우선 분류하고, 없으면 개인으로 분류한다. 개인 태그는 필수가 아니다.
- 완료한 작업은 활성 목록과 분리해 오늘 완료한 항목만 접어서 제공한다. 이는 데일리노트의 미완료 목록 외에 제공하는 앱 기능이다.
- PC 시간대의 날짜로 판정한다(2026-10-12 이전에는 서울 시간 고정). 현재 확인한 Base/날짜 형식에 맞춘 구현이며 임의의 Bases 수식을 해석하지는 않는다.


## 수정과 복구

우클릭 상태 메뉴는 TaskNotes 설정의 상태 목록(설정이 없으면 기본 네 상태 `none`, `open`, `in-progress`, `done`)을 쓴다. 더블클릭 편집은 상태·우선순위·예정일·마감일·본문을 수정한다. 제목은 파일명/링크 정책 때문에 유지한다. 알 수 없는 기존 상태·우선순위는 다른 필드를 수정할 때 그대로 둔다. 변경하는 날짜는 유효한 YYYY-MM-DD 또는 빈 값이어야 한다.

원문 SHA-256이 열었을 때와 같아야 저장한다. 변경할 YAML 스칼라만 치환해 주석·알 수 없는 속성·프로젝트 링크·BOM·줄바꿈을 보존한다. 본문은 편집한 경우에만 변경한다. 반복 작업은 회차 처리를 아직 지원하지 않아 수정하지 않는다. 완료 전환은 완료일을 기록하고 완료 취소는 완료일을 null로 바꾼다. 모든 실제 변경에 수정일을 기록한다.

볼트/폴더 전환과 저장은 main에서 직렬화한다. 경로·링크·파일 크기·단일 하드링크를 검사하고, 백업 성공 후 같은 폴더의 임시 파일에 새 내용을 기록한다. 교체 직전에 원문을 다시 읽어 해시를 검사하고, 교체 후 재조회한 해시도 확인한다. Obsidian/동기화 프로그램과 공유하는 파일 잠금은 없으므로 마지막 검사와 교체 사이의 극히 짧은 외부 수정 경쟁까지 완전히 막는 것은 아니다. 원문 백업을 보존하고 저장 후 예상치 못한 변경은 오류로 알린다.

백업을 복구할 때는 JSON의 볼트·상대 경로와 원문을 먼저 확인하고, 현재 파일도 따로 보관한 뒤 필요한 내용을 반영한다. 앱 안의 자동 복원 UI는 아직 없다.

검증 추가: 33개 계약/파일 테스트 및 합성 Electron 시험으로 우클릭 상태, 더블클릭 편집, 실제 파일 저장, 완료/취소, 초안 보존, 외부 수정 충돌, 파일 링크/경로 거부, 백업 원문 일치 등을 확인한다. 사용자 노트는 쓰기 시험에 사용하지 않는다.

## 확장 가능한 분류와 드래그 이동 (2026-09-17)

기본 분류 목록은 `업무`, `개인`이며 `＋`에서 분류 태그를 등록한다. 임의의 기존 주제 태그를 자동으로 전부 분류로 간주하지 않는다. 등록한 분류와 같은 기존 태그가 있으면 조회 때 바로 분류에 반영한다. 분류 목록은 앱 프로필의 `categories/<볼트 경로 해시>.json`에 저장하며, 볼트 전환·재실행·작업 폴더 변경에도 해당 볼트의 분류를 복원한다. 분류 설정은 다른 기기에 자동 동기화되지 않지만 작업의 태그 수정은 원본 Markdown에 저장된다.

전체/검색/완료 목록은 분류별 구분선으로 묶고, 그룹 내부는 조회 결과의 정렬을 유지한다. 업무가 우선하며 그 다음 등록된 분류 태그를 적용하고, 일치하는 분류가 없으면 개인으로 표시한다. 여러 분류 태그가 있는 기존 작업을 읽을 때 중복 표시하지 않는다. 기본 데일리 Base의 개인 필터는 업무 외 전부를 포함하므로, 향후 새 분류를 데일리노트에도 독립 표시하려면 그 Base를 별도로 확장해야 한다. 앱이 Base 파일이나 템플릿을 자동 수정하지는 않는다.

드래그 시작 때 잡은 작업 경로와 원문 revision으로 저장을 요청한다. 대상 그룹/탭에 놓으면 기존 등록 분류 태그를 제거하고 대상 태그 하나를 넣는다. `task` 및 분류로 등록하지 않은 다른 태그는 유지한다. 같은 분류로의 이동, 외부 드래그, 반복 작업은 저장하지 않는다. 빈 그룹과 현재 선택하지 않은 탭도 드롭 대상이다. 저장 중에는 추가 변경을 막고, 성공 응답과 원문 재조회 뒤 목록을 갱신한다. 외부 수정 충돌은 저장을 거부하고 최신 목록으로 복귀한다.

태그 편집은 YAML의 tags 값 범위만 다시 직렬화한다. 순서/공백 표시는 정규화될 수 있으며, 유지하는 태그의 값과 주석, 나머지 속성·본문·BOM·줄바꿈은 보존한다. 이전 원본 백업과 저장 후 해시 검사는 상태/본문 수정과 동일하다. 별칭·앵커 등 안전하게 편집할 수 없는 형태는 거부한다.

파일 테스트는 flow/block/scalar 태그, 줄바꿈·주석·본문 보존, 개인/업무/추가 분류의 원본 변경, 등록되지 않은 분류와 충돌 거부를 검증한다. 합성 Electron 시험은 실제 HTML 드래그, 비어 있는 그룹과 필터 탭으로 이동, 새 분류 재실행 유지, 볼트 간 격리, 440px 창에서 9개 탭 표시를 검증한다. 사용자 볼트는 쓰기 시험에 사용하지 않는다.

상태 동그라미는 원본 상태값을 기준으로 없음(연회색 #cccccc, 빈 원), 시작(회색 #808080), 진행 중(파랑 #0066cc), 완료(초록 #00aa00, 체크)로 표시한다. 2026-09-17 확인한 TaskNotes 색상을 적용했으며 목록과 상태 메뉴가 같은 표시를 사용한다. 플러그인 색상 설정의 실시간 연동은 아니다.

## 완료 탭 및 예전 영어 속성 호환 (2026-09-17)

`completed`는 분류 태그가 아닌 상태 전용 조회 범위다. 완료 탭은 검색 경로를 사용해 선택한 작업 폴더와 하위 폴더의 완료 작업을 모든 날짜에서 조회한다. 기존 오늘 완료 접기 영역은 유지한다. 완료일이 없는 작업도 포함하며 최근 완료일 순, 같은 날짜는 경로 순으로 정렬한다. 검색은 완료 작업에 한정하고 100개씩 페이지를 추가한다. 표시 수가 전체 수가 아닐 때 + 기호를 붙인다. 분류 구분선 안에서도 이 순서를 유지한다. 완료 탭 자체는 드롭 대상이 아니며, 표시된 작업은 분류 구역/분류 탭으로 드래그할 수 있다.

속성 읽기는 TaskNotes 설정의 이름을 먼저, 그다음 TaskNotes 기본 이름(`status`, `priority`, `scheduled`, `due`, `completedDate`, `dateModified`), 그다음 다른 표기(한국어 `상태` `우선순위` `예정일` `마감일` `완료일` `수정일`, 예전 `completed` `modified`) 순으로 찾는다. 앞의 이름이 null이면 뒤의 값을 되살리지 않는다. 서로 다른 값이 함께 있으면 CONFLICTING_FIELDS 경고를 남긴다. `created`는 목록 판정에 사용하지 않으며, 수정 시 수정일 속성은 노트에 원래 있는 이름을 쓴다.

상태 값은 TaskNotes 설정의 목록을 따르고, 설정이 없으면 TaskNotes 기본 네 상태(`none`, `open`, `in-progress`, `done`)를 쓴다. 노트가 내장 상태를 다른 표기(`todo`, `completed`, 한국어 `없음` `시작` `진행 중` `완료`)로 적었으면 같은 상태로 본다. 원본 상태값은 별도 보존한다. 알 수 없는 사용자 상태는 완료로 추정하지 않고 경고를 유지한다. 기존 날짜 유효성 검증을 유지하므로 임의 날짜 문자열까지 모두 지원하는 것은 아니다.

편집은 원본에 있는 필드명으로 저장한다. 노트에 없는 속성은 TaskNotes 설정의 이름으로 추가하되, 노트의 다른 속성이 모두 TaskNotes 기본 이름(또는 모두 한국어 이름)이고 설정이 그 속성에 다른 이름을 주지 않았다면 같은 표기로 추가해 한 노트에 두 가지 표기가 섞이지 않게 한다. 상태 값은 목록의 `value`로 쓴다. 같은 필드의 서로 다른 표기가 함께 있으면 요청한 변경에 해당하는 기존 키들을 함께 갱신해 모순을 남기지 않는다. 수정하지 않은 필드와 생성 시각은 보존한다. 파일 백업·원문 해시 충돌 검사·저장 후 검증은 동일하게 적용한다. 노트를 일괄 변환하지 않는다.

영어 작업 필드 호환은 별도의 합성 노트로 검증했다. 파일 테스트는 103개 완료 작업의 페이지 처리, 오래된/완료일 없는 작업, 한영 혼합 충돌 및 원래 영어 필드로 저장을 검증한다. Electron 시험은 완료 탭·검색·영어 작업 표시·완료 취소·빈 목록과 볼트 전환을 검증한다.


## 단축키 설정 (2026-09-18)

동작(Ctrl+K) → 볼트 설정의 단축키 입력란에서 키 조합을 누르고 저장한다. Ctrl 또는 Alt가 필수이며 Shift를 추가할 수 있다. 문자·숫자·F1~F24·방향키·Space 등의 키를 지원하며, 한글 키보드에서도 물리 키 위치를 사용한다. 단독 키와 Windows 키 조합은 받지 않는다. 기본값은 Ctrl+Shift+Space다.

앱 프로필의 `shortcut.json`에 저장하며 볼트 선택과 독립적으로 유지한다. 신규 조합을 먼저 등록하고 임시 파일에서 설정 파일로 교체한 뒤 기존 조합을 해제한다. 등록 실패나 파일 저장 실패는 기존 조합과 저장값을 보존한다. 앱 실행 때 저장값을 복원하고, 당시 다른 앱이 키를 점유하면 설정 화면에 안내한다. 입력란에 포커스가 있는 동안 기존 전역 단축키가 창을 숨기지 않도록 하며, 포커스 이탈·창 숨김·설정 종료 시 정상 동작으로 돌아온다.

파일 테스트로 유효성, 저장·재실행, 충돌, 저장 실패 복구, 잘못된 설정 복구, 동시 변경 방지를 검증한다. Electron 시험으로 입력란·저장·충돌 안내·재실행 복원을 확인한다. 충돌 응답은 테스트에서 대체하며, 물리적인 OS 전역 키 입력 확인과는 구분한다.


## 이전 화면으로 돌아가기 (2026-09-18)

마우스 뒤로가기, Esc, Alt+←는 같은 뒤로가기 동작을 사용한다. 열린 메뉴·분류 입력을 먼저 닫고, 편집 중에는 미저장 초안을 확인한다. 버리기 확인에서 다시 뒤로가면 확인창만 닫아 초안으로 돌아간다. 화면 이력에 상세·편집·설정·분류 탭·검색을 보관하며 검색 문자열의 연속 입력은 한 단계로 묶는다. 볼트를 바꾸거나 해제하면 이전 볼트의 이력을 지운다. 이력이 없는 첫 화면에서는 창을 숨기지 않는다.

기존에는 app-command만 받았으나 보조 버튼의 DOM mouseup(button=3)과 BrowserBack/Alt+Left 경로도 처리한다. 마우스 기본 브라우저 이동은 막고, 같은 입력이 DOM과 네이티브 양쪽에서 중복 전달되면 한 번만 뒤로간다. Chromium Input.dispatchMouseEvent의 back 버튼으로 실제 렌더러 전달 경로를 검증한다. 사용자 마우스 하드웨어·드라이버의 물리 입력까지 확인했다는 의미는 아니다.

## 검색 팝업과 테마 (2026-09-21)

검색은 Ctrl+F나 목록의 작은 검색 버튼으로 연다. 검색 화면 자체를 탐색 기록에 넣어 상세/편집에서 돌아올 때 검색어·분류를 복원한다. 팝업 안의 입력과 필터 변경은 뒤로가기 기록을 늘리지 않으며, 팝업을 닫으면 진입 전 화면으로 돌아간다. 모달이 열려 있는 동안 창 제목 표시줄/푸터는 inert 처리하고 Tab 포커스를 팝업 안에 유지한다.

블랙/화이트 테마는 renderer의 localStorage `taskmanager-theme`에 저장한다. 초기 HTML이 외부 theme.js를 스타일시트보다 먼저 읽어 저장된 테마를 적용한다. CSP의 inline script 허용이나 새로운 파일 접근 권한은 추가하지 않는다. 테마 저장 실패 시 현재 실행에는 적용하고 다음 실행에 유지하지 못함을 안내한다.

합성 Electron 검증에 상단 입력칸 제거, 검색 팝업 열기/닫기/검색 복원, 키보드 포커스, 화이트·블랙 전환과 재시작 유지, 440px 폭 화면을 포함한다.
