# TaskNotes가 기본으로 제공하는 것 (이 앱이 따라야 할 기준)

이 문서는 앱을 TaskNotes와 맞추기 위한 기준 자료입니다. 앞으로 작업 속성을 읽거나 쓰는 기능을 만들 때 먼저 여기를 확인합니다.
시간 처리, 필드 이름, 반복 항목 문제가 모두 "TaskNotes가 실제로 어떻게 하는지" 모르고 만들어서 나중에 고친 것이라, 같은 일을 반복하지 않으려고 만들었습니다.

## 출처와 확인 수준

| 출처 | 내용 | 신뢰 |
|---|---|---|
| 설치된 플러그인 코드 (`main.js`, 버전 4.13.6) | 기본 설정, 기본 필드 이름, 관계 계산, 완료·해제 동작 | 실제 동작의 근거 |
| 공식 규격 (`callumalpass/tasknotes-spec`, 02·03·04·05·10·11장) | 필드 모델, 날짜 규칙, 반복, 관계, 알림, 링크 해석 | 이 앱이 따라야 할 기준 |
| 공식 문서 (`tasknotes.dev`, `docs/features/task-management.md`) | 화면 기능 설명, 프로젝트·하위 작업·차단 | 보조 |

**확인하지 못한 것:** 옵시디언과 TaskNotes를 실제로 실행해서 양쪽 반영을 본 적은 없습니다. 아래는 코드와 규격을 읽은 결과입니다.

## 1. 작업 노트의 구조

작업은 마크다운 노트 한 개입니다. 속성(frontmatter)이 작업의 의미를 정하고, 본문은 자유 메모입니다. 작업 노트인지는 설정에 따라 정해지며 기본은 `task` 태그입니다(식별 방식 `tag`, 태그 이름 `taskTag`, `task/하위`도 포함). 속성으로 구분하도록(`taskIdentificationMethod: property`, `taskPropertyName`, `taskPropertyValue`) 바꿀 수도 있고, 이 앱은 두 방식을 모두 따릅니다.
제목은 기본적으로 **파일 이름**에 저장됩니다(`storeTitleInFilename: true`).

| 속성 (TaskNotes 기본 이름) | 형식 | 의미 | 이 앱 |
|---|---|---|---|
| `title` | 글 | 제목. 기본은 파일 이름 | 읽음 (편집 안 함) |
| `status` | 글 | 설정의 상태 값 중 하나 | 읽기·쓰기 |
| `priority` | 글 | none/low/normal/high 등 설정 값 | 읽기·쓰기 |
| `due` | 날짜 또는 날짜+시간 | 마감 | 읽기·쓰기 |
| `scheduled` | 날짜 또는 날짜+시간 | 예정(시작) | 읽기·쓰기 |
| `completedDate` | 날짜 | 완료한 날 | 읽기·쓰기 |
| `dateCreated`, `dateModified` | 날짜+시간 (UTC, 초 단위) | 만든 때, 고친 때 | 수정일만 씀 |
| `tags` | 목록 | 태그 (이 앱은 분류로 사용) | 읽기·쓰기 |
| `contexts` | 목록 | 장소·상황 (`@office` 식) | 없음 |
| `projects` | 링크 목록 | 속한 프로젝트·상위 작업 (`[[이름]]`) | 없음 |
| `blockedBy` | 객체 목록 | 이 작업을 막는 작업 | 없음 |
| `timeEstimate` | 정수(분) | 예상 시간 | 없음 |
| `timeEntries` | 객체 목록 | 시간 기록 | 없음 |
| `reminders` | 객체 목록 | 알림 | 없음 |
| `attachments` | 링크 목록 | 첨부 파일 | 없음 |
| `recurrence` 외 | 문자열 등 | 반복 | 반복 여부만 판정 |
| 사용자 정의 필드 | 임의 | 사용자가 정한 속성 | 없음 |

속성 이름은 설정(`fieldMapping`)으로 바꿀 수 있고, 앱은 이를 읽어 따라갑니다(상태·우선순위·예정일·마감일·완료일·수정일).

## 2. 날짜와 시간

- **날짜만**: `YYYY-MM-DD`. 하루를 뜻하며 시간대로 옮기지 않습니다.
- **날짜+시간**: 규격의 표준은 UTC `YYYY-MM-DDTHH:MM:SSZ`(초 단위, 소수점 초 금지)이고, 시간대 없는 값은 엄격 모드에서 거부합니다. 그러나 **플러그인은 예정·마감에 시간을 붙일 때 `YYYY-MM-DDTHH:mm`(시간대 없음)으로 씁니다**(플러그인 코드에서 `날짜T시:분`으로 이어 붙이는 것을 확인). 이 앱은 시간대 없는 값을 PC의 시간대로 읽습니다(플러그인과 같음).
- **저장 단위 유지**: 다른 항목을 고칠 때 날짜를 날짜+시간으로 바꾸거나 그 반대로 바꾸면 안 됩니다.
- **오늘·미룸 판정**: PC 시간대의 달력 날짜 기준입니다. 마감일이 어제 이전이고 미완료면 늦은 것이고, 마감 당일은 늦은 것이 아닙니다.
- **수정일 형식**: 규격은 UTC 초 단위(`2026-09-30T02:00:00Z`)입니다. 이 앱도 이 형식으로 씁니다.

## 3. 상태, 우선순위, 완료

상태 목록은 설정(`customStatuses`)에 있고 각 상태는 `id`, `value`(노트에 쓰이는 값), `label`(화면에 보이는 이름), `color`, `isCompleted`, `order`, 자동 보관 설정을 가집니다.

- **기본값은 영어**입니다: `none`/`open`/`in-progress`/`done` (표시 이름 `None`/`Open`/`In progress`/`Done`), 기본 상태 `open`, 기본 우선순위 `normal`. 사용자가 설정에서 다른 이름(예: 한국어 `없음/시작/진행 중/완료`)으로 바꿔 쓸 수 있고, 앱은 그 설정을 따릅니다.
- **노트에는 `value`가 저장되고, 화면에는 `label`이 보입니다.** 이 앱도 화면에 `label`을 보여주고 `value`를 저장합니다.
- **완료(비반복)**: 상태를 완료 상태로 바꾸고, 완료일을 그날로 기록하고, 수정일을 갱신합니다.
- **다시 열기(비반복)**: 상태를 활성 상태로 되돌리고 **`completedDate`를 지웁니다**(플러그인은 값을 `undefined`로 만들어 속성이 사라짐). 이 앱도 다시 열거나 날짜를 비우면 속성을 지웁니다.
- 완료일은 완료 상태의 비반복 작업에 필수입니다.

## 4. 관계: 프로젝트, 상위·하위 작업, 차단

관계는 **노트 링크**로 표현합니다. 링크는 `[[이름]]`, `[[폴더/이름]]`, `[[이름|별칭]]` 형식이고, 이름만 있으면 볼트 전체에서 같은 파일 이름을 찾습니다(여러 개면 모호해서 실패).

- **프로젝트(`projects`)**: 링크 목록. **볼트의 어떤 노트든** 프로젝트가 될 수 있습니다(작업 노트가 아니어도 됨).
- **상위 작업(parents)**: `projects` 항목 중 *작업 노트*로 풀리는 것.
- **하위 작업(subtasks)**: 계산되는 값입니다. 다른 작업들의 `projects`가 이 작업을 가리키면 그 작업들이 하위 작업입니다. 하위 작업은 하위 쪽 노트에만 기록되고, 상위 노트에는 아무것도 적히지 않습니다.
- **차단 원인(`blockedBy`)**: 객체 목록 `{ uid: "[[작업]]", reltype: FINISHTOSTART, gap: P1D }`. `reltype`은 `FINISHTOSTART`/`STARTTOSTART`/`FINISHTOFINISH`/`STARTTOFINISH`, `gap`은 ISO 기간(선택).
- **차단 중(blocking)**: 계산되는 값입니다. 다른 작업의 `blockedBy`가 이 작업을 가리키면 그 작업들이 "이 작업이 막고 있는 작업"입니다.
- **막힘(blocked) 판정**: 막는 작업 중 완료되지 않은 것이 하나라도 있으면 막힌 것입니다. `reltype`과 `gap`은 보존만 하고 판정에는 쓰지 않습니다(규격 v0.1). 찾을 수 없는 대상은 설정에 따라 막힌 것으로 칩니다.
- 자기 자신을 막을 수 없습니다. 프로젝트 소속과 차단은 서로 독립입니다.

### 이 앱이 관계를 바꾸는 방식

작업 상세 화면에서 관계를 이름으로 찾아 추가·해제합니다(파일을 고르지 않습니다). 네 가지 변경이 있고, **링크는 항상 그 링크를 가진 쪽 노트 한 곳에만** 씁니다.

| 상세 화면에서 | 쓰는 노트 | 바뀌는 속성 |
| --- | --- | --- |
| 프로젝트·상위 작업 추가/해제 | 이 작업 | 이 작업의 `projects` |
| 하위 작업 추가/해제 | 그 하위 작업 | 그 작업의 `projects` (이 작업을 가리키는 링크) |
| 차단 원인 추가/해제 | 이 작업 | 이 작업의 `blockedBy` |
| 막고 있는 작업 추가/해제 | 막히는 작업 | 그 작업의 `blockedBy` |

- **링크 모양**: 항상 위키링크입니다. 같은 이름의 노트가 볼트에 하나뿐이면 `[[이름]]`, 여럿이면 `[[폴더/이름]]`(`.md` 없이). 쓰기 전에 규격대로 다시 읽어 *고른 노트로 풀리는지* 확인하고, 아니면 쓰지 않습니다. TaskNotes의 "프론트매터에 마크다운 링크 사용" 설정은 따르지 않습니다(읽기는 마크다운 링크도 지원).
- **항목 모양**: `projects`는 따옴표 친 링크 목록, `blockedBy`는 `uid`와 `reltype: FINISHTOSTART`를 가진 객체 목록입니다. 이미 있는 항목의 `reltype`·`gap`과 노트의 다른 속성·본문은 그대로 둡니다. 목록이 비면 그 속성을 노트에서 뺍니다. 속성 이름은 노트가 쓰는 이름(설정의 이름, 기본 이름, `blocked_by`)을 따릅니다.
- **추가·해제는 "지금 노트" 기준으로 적용됩니다**: 화면에 보이던 값을 덮어쓰지 않고, 쓰는 순간 노트를 읽어 그 위에서 링크 하나를 넣거나 뺍니다. 이미 있는 링크를 또 추가하거나 없는 링크를 해제하면 아무것도 쓰지 않습니다. 쓰는 사이 노트가 바뀌면 거부합니다. 쓰기 전 원본은 백업하고, `dateModified`도 갱신합니다.
- **고리 방지**: 서로가 서로의 상위 작업(또는 차단 원인)이 되는 변경, 자기 자신과의 연결은 거부합니다.
- **반복 작업**: 반복 작업의 노트는 쓰지 않습니다. 반복 작업이 *다른 작업이 가리키는 쪽*이 되는 것(예: 반복 작업을 상위 작업으로 고르는 것)은 가능합니다.
- **링크가 아닌 항목**: 링크로 읽히지 않는 항목(글자만 있는 값 등)은 건드리지 않고 그대로 둡니다. 가리키는 노트를 못 찾는 링크는 노트에 적힌 텍스트 그대로 지정해 해제할 수 있습니다.
- **볼트가 너무 커서(50,000개 초과) 색인을 못 만든 경우** 관계를 확인할 수 없으므로 수정하지 않습니다.

## 5. 반복 작업

- **시리즈**: `recurrence`(RRULE 문자열), `recurrence_anchor`(`scheduled`/`completion`), `complete_instances`, `skipped_instances`로 어느 날 회차를 완료·건너뛰었는지 기록합니다.
- **개별 노트로 만든 회차(materialized occurrence)**: 각 회차가 자기 노트를 갖고 `recurrence_parent`(부모 링크)와 `occurrence_date`를 가집니다. 부모에는 `occurrence_materialization`, `occurrence_next_trigger`, `occurrence_template` 등이 있습니다.
- **회차 노트를 완료하면** 그 노트를 완료할 뿐 아니라 **부모의 `complete_instances`에 그 날짜를 더하고**, 설정에 따라 다음 회차 노트까지 만듭니다. 상태만 바꾸면 부모와 어긋납니다.
- 따라서 이 앱은 시리즈와 회차 노트를 모두 **읽기 전용**으로 두어야 합니다. 이 앱은 시리즈 속성과 회차 노트 속성(`recurrence_parent`, `occurrence_*`)이 있는 노트를 모두 읽기 전용으로 둡니다.

## 6. 그 밖의 기능

- **알림(`reminders`)**: `{ id, type: relative|absolute, relatedTo: due|scheduled, offset: ISO 기간, absoluteTime, description }`.
- **시간 기록(`timeEntries`)**: `{ startTime, endTime?, description? }`. `endTime`이 없으면 진행 중인 기록이며 작업당 하나만 허용됩니다. 완료하면 자동으로 멈추는 설정이 있습니다.
- **예상 시간(`timeEstimate`)**: 분 단위 정수.
- **컨텍스트(`contexts`)**: 문자열 목록(보통 `@` 접두).
- **첨부(`attachments`)**: 링크 목록.
- **보관**: 상태별 자동 보관, 보관 태그.
- **포모도로, 캘린더(구글·아웃룩·ICS) 연동, 사용자 정의 필드, Bases 보기, HTTP API**: 플러그인 기능이며 작업 노트 속성과는 별개입니다.

## 7. 볼트마다 다른 점

- 사람마다 쓰는 속성이 다릅니다. 이 앱은 TaskNotes 설정(`data.json`)의 필드 이름과 상태 목록을 따르고, 설정이 없으면 TaskNotes의 기본값을 씁니다.
- 프로젝트로 쓰는 노트는 TaskNotes 작업이 아닌 평범한 노트인 경우가 많고, 그 속성(상태, 기간, 협업자 등)은 사람마다 다릅니다. 앱은 그 노트의 속성을 해석하지 않고 이름과 위치만 씁니다.
- 일부 노트에 `created`/`modified` 같은 예전 영어 이름이 함께 남아 있을 수 있습니다. 읽기는 모두 받아들이고, 쓸 때는 노트가 이미 쓰는 이름을 따릅니다.

## 9. 메인 앱 정보 구성안

1단계(읽기 전용 표시)는 구현됨: `packages/tasknotes/links.ts`(링크 해석, 규격 11장), `relations.ts`(프로젝트·하위·차단 계산), `apps/desktop/vault-index.ts`(볼트 노트 목록, 5만 개 상한). 공개용이므로 폴더 이름이나 속성 이름을 가정하지 않고 TaskNotes 설정을 따릅니다.

- **목록 행**: 소속 프로젝트 이름(칩), 하위 작업 진행률(`2/5`), 막힘 표시. 위젯은 지금 정보량을 유지합니다.
- **상세 화면 (읽기)**:
  - 상위: 소속 프로젝트·상위 작업 (클릭하면 이동)
  - 하위: 하위 작업 목록과 상태, 진행률
  - 관계: 차단 원인(대상, 관계 유형, 완료 여부), 차단 중인 작업
  - 일정: 예정일, 마감일, 시간, 완료일
  - 부가: 컨텍스트, 예상 시간·기록 시간, 알림, 태그, 만든 날, 고친 날, 파일 위치, "옵시디언에서 열기"
- **편집**: 1단계 읽기 전용 관계 표시와 2단계 프로젝트·차단 추가/제거는 구현됨. 이후 컨텍스트·예상 시간·알림.
- **전제 작업**: 볼트 전체 노트 이름 색인(링크 해석용). 지금은 작업 폴더만 읽으므로 프로젝트 노트(`Projects/`)를 찾으려면 필요합니다.
